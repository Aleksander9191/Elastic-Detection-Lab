

## Objective

Validate whether Elastic Stack, Elastic Agent and Sysmon successfully capture process creation events generated during local account enumeration and determine whether Elastic Security can detect the activity using built-in or custom detection rules.

---

# Lab Environment

| Component | Value |
|-----------|-------|
| SIEM | Elastic Stack 9.4 |
| Endpoint | Windows 10 Pro |
| Telemetry | Sysmon + Elastic Agent |
| Attack Framework | Atomic Red Team |
| Technique | MITRE ATT&CK T1087.001 |

---

# Attack Simulation

The Atomic Red Team simulation was executed using the following command:

```powershell
Invoke-AtomicTest T1087.001 -TestNumbers 8 `
-PathToAtomicsFolder C:\AtomicRedTeam\atomics
```

The test performs native Windows account discovery using:

```text
net user
dir C:\Users\
cmdkey.exe /list
net localgroup "Users"
net localgroup
```

# Investigation

Immediately after executing the Atomic Test, Elastic received multiple Sysmon Event ID 1 (Process Create) events.

One example event contained:

| Field | Value |
|-------|-------|
| Event ID | 1 |
| Image | `C:\Windows\System32\net1.exe` |
| Parent Image | `C:\Windows\System32\net.exe` |
| Command Line | `net1 localgroup` |
| User | `CORP\Administrator` |
| Integrity Level | High |

The observed process chain was:

```text
Atomic Test
      │
      ▼
net.exe
      │
      ▼
net1.exe
```

Windows internally delegates several `net.exe` operations to `net1.exe`, which was successfully captured by Sysmon.

# Telemetry Assessment

The collected telemetry includes:

- executable path
- command line
- parent process
- parent command line
- process identifiers
- user context
- integrity level
- process GUID

This provides sufficient visibility for process-based detection engineering.

### Observation

Sysmon fields are currently stored primarily under:

```text
winlog.event_data.*
```

Equivalent ECS fields such as:

- process.name
- process.command_line
- process.parent.name

are not currently populated.

Although this limits ECS-based detections, the raw Sysmon telemetry remains sufficient for threat hunting and custom detection development.

---

# Existing Detection Analysis

The next step was to determine whether Elastic Security already detects this activity.

The installed prebuilt detection rules were reviewed.

One relevant rule was identified:

> **Account Discovery Command via SYSTEM Account**

This rule detects account discovery commands executed specifically by the **SYSTEM** account.

The Atomic Red Team simulation was executed as:

```text
CORP\Administrator
```

Therefore the rule conditions were not satisfied.

No Elastic alert was generated.

This confirms that the lack of an alert was expected and was not caused by missing telemetry.

# Custom Detection Rule

Since no existing rule matched this scenario, a custom detection rule was created.

### Detection Logic

```kql
event.code:1 and (
  winlog.event_data.OriginalFileName:"net.exe" or
  winlog.event_data.OriginalFileName:"net1.exe" or
  winlog.event_data.OriginalFileName:"cmdkey.exe"
)
```

# Detection Validation

The Atomic Red Team simulation was executed again after enabling the custom detection rule.

Elastic Security successfully generated alerts for the observed activity.

| Metric | Result |
|---------|--------|
| Atomic Test | T1087.001-8 |
| Detection Rule | Local Account Discovery via Native Windows Utilities |
| Alert Generated | Yes |
| Number of Alerts | 7 |

The alerts corresponded to execution of:

- net.exe
- net1.exe
- cmdkey.exe

confirming that the custom rule successfully detected the simulated account discovery activity.

# Lessons Learned

- Elastic successfully collected all Sysmon Process Create events.
- Raw Sysmon telemetry provided sufficient data for detection engineering.
- The existing Elastic prebuilt rule did not trigger because it was limited to the SYSTEM account.
- A custom KQL detection rule successfully detected the Atomic Red Team simulation.
- Future improvements may include ECS normalization, EQL sequence rules and parent-child process correlation.

---

# Conclusion

This project demonstrates a complete detection engineering workflow:

1. Simulate an adversary technique.
2. Verify telemetry collection.
3. Analyze available evidence.
4. Evaluate existing detection coverage.
5. Develop a custom detection rule.
6. Validate the rule using Atomic Red Team.

The resulting workflow provides a repeatable methodology for developing and validating Elastic Security detections mapped to the MITRE ATT&CK framework.
